The rules are:

1. There is a predefined const object 'flow' with following methods:
then( context => expression ) - executes lambda expression with context as input
thenSet( modelAttributeName, context => expression) - executes lambda expression with context as input and stores the result in view model.

2. Any logic must be only in lambda expressions.

3. The code is javascript, but do not use any default standard Javascript functions. Use '=>' operator for lambda expressions.

4. Code starts with 'flow'.

5. Expressions can store attributes in view model using context.model.set(key, value).

6. Expressions can read attributes from view model stored data using context.model.get(key).

7. Lambda expression input context object has the following fields:
params - a map of input parameters. To read a parameter write: context.params.get("parameterName")
services - a service with following operations:
model - view model map
result - result from previous 'then' or 'thenSet' call

The full specification of context is:
${CONTEXT_SPECIFICATION}

void user.setFirstName(String)
String user.getLastName()

organization:
Long organization.getId()

11. You must not use any methods except for those specified above. Use explicit getters and setters in the code. This is very important rule.

12. Metadata is exactly one of:
- "GET;[actionUrl];HTML" - when the code prepares view model
- "POST;[actionUrl];MODEL_AS_JSON" - when the code is action and "response" is object.
- "POST;[actionUrl];STREAM" - when the code is action and "response" is a value from service returning stream.
where [actionUrl] is suitable relative url for page or action, eg. "doSomeAction" and never starts with '/'.
